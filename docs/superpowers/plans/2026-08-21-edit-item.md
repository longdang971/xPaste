# Editing an item — Implementation Plan

**Goal:** The preview popover gains an edit mode for Text and Link items, keeping formatting.

**Design:** `docs/superpowers/specs/2026-08-21-edit-item-design.md`

**Architecture:** The content rules (what type an item is, how formatting is re-encoded) are pure and
tested. `ClipboardStore` owns the write and the cache purge. The popover is the only new UI.

**Order:** the rules, then the store, then the staleness plumbing — which is the part that breaks
silently — then the popover.

---

## Task 1 — `ClipboardItem.contentType(for:)`

- [x] Lift the http/https test out of `from(pasteboard:)` into `static func contentType(for: String)`
- [x] `from(pasteboard:)` calls it, so capture and editing cannot drift apart

**Tests:** `http://` and `https://` are `.url`; `ftp://`, `mailto:`, a bare domain and prose are
`.text`; a link with whitespace around it is still a link.

## Task 2 — `ItemEdit`: formatting out of the editor

- [x] `ItemEdit.rtf(from: NSAttributedString) -> Data?`, nil for an empty string
- [x] Callers pair it with `NSPasteboard.PasteboardType.rtf.rawValue`

**Tests:** bold and a background colour survive a round-trip through RTF and back; an empty string
yields nil.

## Task 3 — `ClipboardItem.revision`

- [x] `var revision: Int?` plus its `CodingKeys` entry — optional so items already on disk decode
- [x] Exposed as a non-optional `contentRevision: Int` for callers that just want a number

**Tests:** an item decoded from JSON with no `revision` key loads with revision 0.

## Task 4 — `ClipboardStore.updateContent`

- [x] `updateContent(id:text:richData:richType:)`
- [x] Refuses a non-Text/Link item and an empty or whitespace-only result
- [x] Re-classifies via `contentType(for:)`, bumps the revision, leaves timestamp and pin alone
- [x] Purges the id-keyed caches, then `writeMetadata`

**Tests:** text changes; revision bumps; text→link and link→text re-classify; timestamp and
`isPinned` unchanged; empty refused; image refused; unknown id is a no-op; the change survives a
reload from disk.

## Task 5 — Purging what is keyed by id

- [x] `RichTextRenderer.forget(_ id: UUID)` drops the parse cache entry
- [x] `ClipboardItemCard.forgetContent(for: UUID)` drops cardText, richPreview, fileText, pathImage
- [x] `ClipboardStore.updateContent` calls both, with a comment naming the trap

## Task 6 — Making the card notice

- [x] `CardTaskKey` carries the revision, so `.task` re-runs on an edit
- [x] `RichCardPreview` records `builtForRevision`; `isUsable` treats a mismatch as a miss
- [x] The `.task` assigns `fileText`, `pathImage` and `detectedFilePath` **totally**, nil included —
      editing a path item into prose must clear them, not leave them behind

## Task 7 — The popover's edit mode

- [x] `EditableRichText`: an `NSTextView` that is editable, seeded once, read on demand through a
      buffer holding a weak reference to the view — no per-keystroke copying
- [x] `PreviewPopoverContent` gains `isEditing`; header shows a pencil for Text/Link, footer shows
      Save and Cancel while editing
- [x] A rich item edits its attributed string; a plain item edits plain text
- [x] For a Link, edit mode replaces the web view with the editor
- [x] Save is disabled while the result is empty
- [x] Entering/leaving edit mode posts `.clipboardAlertShown` / `.clipboardAlertHidden` so Escape
      cancels the edit instead of closing the panel

## Task 8 — Getting there from the card

- [x] `ContentView` gains "Edit…" in `cardMenu`, for Text and Link only
- [x] It opens the popover already in edit mode
- [x] `.panelWillHide` clears the flag, as it already clears a half-finished rename

## Task 9 — Verify

- [x] `xcodegen generate`, full `xcodebuild test` — green, no new warnings
- [x] Inject realistic items into a real store on a temporary directory — PHP, Python, JSON, prose,
      an RTF item, a PNG, a JPEG, a link — and drive **both** new features end to end below the UI:
      suggest → write → read the bytes back; edit → re-read from disk
- [x] Hunt specifically for the interactions the two features have with each other: saving an item
      that was just edited must write the new content, not the cached old one
- [x] Launch the built app against an isolated seeded history (`XPASTE_STORAGE_DIR`) — panel opened
      and drew all nine cards over two rounds, 0 late frames, clean exit, no crash report

## Still to do — manual

The Save dialog and the edit popover are modal AppKit and cannot be driven by machine. Nothing below
has been exercised:

- the pencil in the preview header, and "Edit…" in the card menu, open the editor
- a formatted item keeps its highlight through an edit; a plain one stays plain
- ⌘S saves the edit while the editor is open, and Escape cancels it without closing the panel
- Save closes the popover and the card behind it shows the new text immediately
- editing a card, then saving it to a file, writes the edited content
